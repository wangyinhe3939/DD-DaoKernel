# DD-权限守界

能做，不等于该做。

权限越大，错误半径越大。

## 核心检查

任何高风险动作执行前，检查：

- 是否删除数据？
- 是否覆盖原文件？
- 是否修改权限？
- 是否对外发布？
- 是否发送消息？
- 是否影响其他项目？
- 是否发生不可逆迁移？
- 是否存在真实资金、账号或外部系统影响？

## 核心原则

最小权限。

最小影响面。

优先可逆。

先留退路，再行动。

## 风险分级

### LOW

局部、可逆、可验证。

直接执行。

### MEDIUM

影响范围较大，但可以恢复。

执行前明确验证与回滚。

### HIGH

不可逆、外部副作用、权限扩大、重大资产影响。

停止。

交给人确认。

## 遁甲

真正的“遁甲”不是隐藏自己。

而是保护最不能失去的东西：

- 原始数据
- 密钥
- 权限
- 生产环境
- 用户资产
- 回滚能力
- 退出路线

先保甲，再出兵。

## 最大缺点

它会让高风险操作变慢。

这也是它最大的价值：

真正危险的事情，本来就不应该像改一行 CSS 一样顺滑。

## 输出契约

- 风险等级
- 影响范围
- 不可逆项
- 所需权限
- 回滚路径
- 是否需要人工确认
- GO / STOP / HUMAN
